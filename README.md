# Project 1 — Production-Style 3-Tier AWS Cloud Project

A production-style 3-tier web application deployed on AWS using Terraform, with private EC2 instances, RDS PostgreSQL, S3, ALB, Auto Scaling, CloudWatch, Secrets Manager, Systems Manager, and GitHub Actions CI/CD.

## 1. Architecture

Internet
   |
   v
Route 53 / Domain (optional)
   |
   v
Application Load Balancer
   |
   +-----------------------------+
   |                             |
   v                             v
EC2 (private-app AZ-a)      EC2 (private-app AZ-b)
Auto Scaling Group (2-4 instances, target-tracking on CPU)
   |                             |
   +---------------+-------------+
                   |
                   v
        RDS PostgreSQL
        (private-db subnets)
                   |
                   v
        S3 (private bucket)

Network layout: one VPC, 2 AZs, 3 subnet tiers (public / private-app / private-db).
One NAT Gateway (cost-optimized) gives the private subnets outbound internet for
package installs and AWS API calls, without any inbound path.

## 3. Technology stack

- App: Node.js 20 + Express, pg for PostgreSQL, aws-sdk for S3, winston for structured JSON logging.
- Infra: Terraform >= 1.7, AWS provider ~> 5.60.
- AWS: VPC, IGW, NAT Gateway, ALB, Auto Scaling Group (EC2, Amazon Linux 2023), RDS PostgreSQL 16, S3, Secrets Manager, IAM, Route 53 (optional), ACM (optional), CloudWatch, Systems Manager.
- CI/CD: GitHub Actions with OIDC federation to AWS.

## 4. Security model

| Component | Exposure |
|---|---|
| ALB | Public (80/443 only) |
| EC2 | Private subnet, only reachable from ALB SG on port 8080 |
| RDS | Private subnet, only reachable from EC2 SG on port 5432 — never public |
| SSH | Disabled entirely — access is via SSM Session Manager |
| Secrets | DB password generated by Terraform, stored in Secrets Manager |
| IAM | Per-resource least privilege |
| S3 | Public access block enabled, SSE-AES256, versioning enabled |
| IMDS | IMDSv2 required |

## 5. Required values you must provide

Copy:

terraform/terraform.tfvars.example

to:

terraform/terraform.tfvars

Fill in:

| Variable | Where to get it |
|---|---|
| aws_region | Your chosen AWS region, e.g. ap-south-1 |
| azs | Two AZs in that region |
| domain_name | Optional domain you own |
| hosted_zone_id | Optional Route 53 hosted zone ID |
| certificate_arn | Optional ACM certificate ARN |

Leave domain_name, hosted_zone_id and certificate_arn blank for the first deployment.

## 7. Deployment

### 1. Clone and configure

git clone https://github.com/REPLACE_WITH_YOUR_USERNAME/REPLACE_WITH_YOUR_REPO.git
cd project-1/terraform

cp terraform.tfvars.example terraform.tfvars

Edit terraform.tfvars.

### 2. Authenticate with AWS

aws configure

### 3. Provision infrastructure

terraform init
terraform fmt -check
terraform validate
terraform plan -out=tfplan
terraform apply tfplan

### 4. Get the ALB URL

terraform output alb_dns_name

### 5. First application deployment

cd terraform

ASG_NAME=$(terraform output -raw asg_name)
BUCKET=$(terraform output -raw s3_bucket_name)
REGION=$(grep aws_region terraform.tfvars | cut -d'"' -f2)

cd ..

tar -czf app.tar.gz -C app .

aws s3 cp app.tar.gz "s3://${BUCKET}/deploys/app-manual.tar.gz"

bash scripts/deploy.sh "$ASG_NAME" "$BUCKET" manual "$REGION"

### 6. Open the application

Open the ALB DNS name in your browser.

## 9. Verification checklist

### VPC and subnets

aws ec2 describe-subnets --filters Name=tag:Project,Values=cloud-project-1

### NAT connectivity

### ASG

aws autoscaling describe-auto-scaling-groups \
  --auto-scaling-group-names cloud-project-1-asg

### ALB target health

TG_ARN=$(aws elbv2 describe-target-groups \
  --names cloud-project-1-tg \
  --query "TargetGroups[0].TargetGroupArn" \

  --target-group-arn "$TG_ARN"

### Application

curl -s http://<alb_dns_name>/api/visits/count

### CloudWatch

  --alarm-name-prefix cloud-project-1

## 10. Failure testing

| Test | Expected result |
|---|---|
| Terminate one EC2 instance | ASG launches a replacement |
| Stop application on one instance | ALB routes traffic to healthy instance |
| Make ALB target unhealthy | Target becomes unhealthy |
| Remove NAT route | Private instance loses external connectivity |
| Revoke EC2 → RDS access | Deep health check returns 503 |
| Stop RDS | Database operations return errors but application stays running |
| Introduce application syntax error | CI test fails and deployment does not run |
| Introduce Terraform error | Terraform validation/plan fails |

## 11. Troubleshooting

### ALB 502

Check:

sudo systemctl status project1-app

sudo journalctl -u project1-app -n 100

### ALB unhealthy target

Check:

curl localhost:8080/health

Confirm the target group port and health-check path match the application.

### EC2 unreachable through SSM

Check:

- SSM agent
- IAM instance profile
- NAT/outbound connectivity

### Application not starting

Check:

journalctl -u project1-app

Usually this means a missing environment variable or npm dependency.

### Application 500 error

Check:

/api/health/deep

Usually this indicates a database connectivity or credentials problem.

### Database connection failure

Check:

- RDS status
- EC2 security group
- RDS security group
- DB_HOST
- Secrets Manager credentials

### DNS failure

Check the Route 53 alias record and ALB DNS name.

### HTTPS problem

The ACM certificate must be issued and must be in the same AWS region as the ALB.

### NAT problem

Check that the private route table has:

0.0.0.0/0 -> NAT Gateway

and that the NAT Gateway is available in a public subnet with an Elastic IP.

### Terraform problem

Run:

terraform validate

terraform plan

Check variable and output names between modules and main.tf.

### GitHub Actions problem

Check:

- OIDC IAM trust policy
- AWS_OIDC_ROLE_ARN secret
- AWS_REGION variable
- S3_BUCKET_NAME variable
- ASG_NAME variable
